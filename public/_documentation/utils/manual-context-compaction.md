# Manual context compaction

This guide describes the source implementation. Final runtime qualification and provider package rollout remain tracked in `planning/manual-context-compaction/tasks.md`.

Under **Chat settings → Context & compaction**, the context meter estimates input occupancy against the selected model’s actual context window. Its accessible description includes input usage and the available reply allowance; an optional maximum comes from AI settings. After a reply, matching history uses provider-reported input usage plus estimates for subsequent messages and attachments. New images use stored dimensions and common OpenAI/Claude geometry rules, with a 1,200-token fallback when the model or dimensions are unknown. Encoded image bytes are never counted as text. Unmeasured PDF cost can remain unknown. Unknown capacity is explicit; the application does not substitute a guessed capacity or silently trim history.

The collapsed card shows context usage and **Compact now**. Click its header to expand or collapse the usage meter, automatic compaction settings, and version history. Choose **Compact now** on the right of the header or **Compact conversation** in a conversation’s history menu. Compaction uses the current chat model automatically, including routed models and model aliases; no separate model selection is required. It checks that model’s context limit before sending. Compaction creates a new conversation with a summary, and the original remains saved. Wait for replies and tools to finish before compacting. Cancelling or changing the source prevents the operation from committing.

**Auto-compact when context is high** is off by default. Turn it on in Context & compaction to compact at 80% estimated context use, once the chat is idle and has eligible settled history. This workspace AI preference (`autoCompactContext`) persists across reloads. Each unchanged source gets one automatic attempt, recorded in workspace KV before inference and retained across reloads and remounts; failed attempts do not loop. Concurrent tabs claim the record atomically. An unsent draft stays available in both the original and its continuation. **Version history** opens the original or a saved version. Progress and Cancel also appear inside Context & compaction.

The auxiliary model must return a JSON envelope with a Markdown string and at least one valid captured landmark. Invalid output gets one corrective attempt; a failed validation preserves the original conversation.

The summary envelope is validated with a strict Zod schema in the browser.
Validation rejects extra fields and runs under the production CSP without
dynamic JavaScript compilation.

The new conversation begins with a collapsed **Context compacted** card. Expand it for the summary and landmarks. **View original** identifies the visible original message ordinal rather than an internal database index. Original and landmark links remain usable when the model cannot use retrieval tools. Reverse links at an original message open its direct branches, including children anchored to the stored tool results displayed inside an assistant reply. Those UI result IDs are navigation hints; the link handler verifies the stored parent, call and thread before opening the child.

The sidebar shows an expand arrow only for chats with forks or compactions. Standalone chats keep their ordinary row. The family header uses the original chat’s title and opens its latest matching activity. Its Rename original conversation and Delete original conversation actions target that original; member actions target the named member. It stays highlighted whenever any chat in that family is open, even while collapsed; individual rows highlight only their own open chat. Expanding it shows a connected timeline, newest first, with subtitles for **Latest compacted version**, **Earlier compacted version**, **Original conversation**, known Retry or Branch. The latest compaction has a highlighted dot. Family rows offer **Go to original** and **Go to latest compaction**. Search can reveal matching children without changing saved expansion. Missing or cyclic lineage remains visible with an unavailable-link explanation. Grouping reads thread metadata, not conversation contents. Expanded families share a lazy metadata fallback within each refresh instead of rescanning all chats for each family.

Hard deletion is refused while a retained child depends on the original. **Move to Trash** preserves that relationship. Historical retrieval never returns deleted text, and a missing original does not invalidate a saved summary.

Database upgrades preserve the existing Files outbox index while adding lineage, history paging, and local request recovery indexes. Upgrading a compaction development database also retains these indexes without rewriting conversation rows or creating startup sync operations.

If input and reply cannot fit, sending stops with `context_full`. Keep the draft, compact, edit it, or select another supported model. A locally blocked new request saves no new turn. An initial native rejection after local persistence keeps the saved turn; Retry can recover that same identity through its local checkpoint. Recovery repeats admission and does not repeat already-run request filters. A changed source or tool set requires explicit new preparation. Later tool-loop overflow preserves accepted results and stops before another provider request.

**Inspect lossy send** is a separate explicit recovery for a locally blocked new request. Inspect the exact old turns proposed for omission, the resulting input/window estimate and reply allowance, then confirm that one request. Editing invalidates that decision. Saved history remains intact; the next ordinary send starts from the full saved projection. Ordinary sends, retries, continuation and tool loops do not implicitly shorten normal user context.

Prompt, attachment, model/routing, tool and preference changes invalidate the current decision. The read-only preview uses attachment metadata without loading file bytes; PDF accounting is independent of the image selection limit. Provider usage is reused only when the message prefix, attachment content identities and request configuration still match. Manual compaction captures the effective routing variant; cancellation preserves the original and draft. Retry in a reference descendant retains its inherited summary and eligible ancestor turns while superseding only the selected local turn.

## Extension and provider boundaries

Retained summaries can use a deleted source while its thread tombstone still
records project ownership. A missing ownership record, a move to another project
or an explicit project exclusion refuses inherited context. Read-only workspace
viewers cannot resolve ambiguous project ownership; an owner or editor chooses
the chat's project.

The existing composer/message registries receive optional compaction callbacks and disabled reasons. `MessageActionContext.compaction`, `MessageAction.visible`, `disabled`, and `disabledReason` are additive; an extension without them retains its prior behavior. Thread-history actions can add a pure reactive `disabledReason({ threadId })` and a read-only asynchronous `inspectDisabledReason({ document })`. The latter runs only while the menu is open and rechecks durable eligibility before execution; subscriptions stop on close or workspace change. Existing actions without these optional fields retain their behavior. Summary rows stay read-only. PageShell receives the committed-child feature event separately from ordinary blank-chat promotion, and opens it only while the initiating pane/workspace remains current. A saved child remains in history if navigation fails.

Core `get_message` and `search_parent` tools derive authority from their captured execution context. Models cannot supply a workspace, actor or replacement thread. Default reads use captured compaction membership in the actual ancestor path. Explicit expansion stays within that path and labels content outside captured scope. Search returns bounded pages, signed continuation cursors, physical fetched-row and processed-byte counts, and an honest incomplete-scan status. An empty partial page does not establish absence: follow its continuation. Changed, replaced, deleted and unavailable originals have separate outcomes. Returned content, neighbors and search matches carry `reference_only: true`; they are fallible historical evidence, never instructions or authorization.

The optional sync gateway capability is `canonicalChatHistory: 'v1'`, with `readChatHistory(actor, query, signal)`. Queries are bounded by-ID or ordered thread pages; the host-only canonical seek protocol supports bounded neighbors. Thread queries return per-thread revisions. Materialized canonical rows are the content source; job records identify execution and retained sync logs are not content history. Existing providers remain valid without the capability.

Background admission resolves canonical readiness before freezing the tool catalog, and the server checks it again before creating a job. Unsupported or unsynced lineage uses the browser bridge or foreground path. A later gap returns `scope_incomplete`. Current membership and `can(workspace.read)` are checked through the existing authorization boundary.

`ai.chat.send:filter:prepare` and acknowledged real-ID `ai.chat.send:filter:commit` are additive request-scoped contracts. Legacy `ai.chat.send:action:before` and `ai.chat.messages:filter:before_send` retain their established once-only post-write order. Side-effecting legacy filters cannot provide universal zero-write final-payload admission until they adopt the pure contract. For Workflows, the qualification target is the separately packaged pure prepare/real-ID commit implementation; the legacy exception is not an accepted final admission guarantee. Build/conformance alone does not establish package activation. No transaction spans inference.

Local failed-native checkpoints use `chat_request_recoveries`, outside the synchronized table set. They contain the final payload and no credentials, bind source/turn/tool identities, and are removed on accepted generation or central thread deletion. SQLite migrations 022–023 and the Convex scaffold reader/revision changes require separately reviewed provider builds, round trips and released pins before rollout. D1 does not advertise the new canonical reader.

Compaction keeps the selected routing variant, including Nitro/Floor suffixes. The current chat model is also the default for routed models and latest aliases.
