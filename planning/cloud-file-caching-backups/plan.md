# Cloud file caching and workspace backup plan

Bound browser storage and make Cloud backups complete. Reuse the existing transfer queue, authorization, upload reservation/commit flow, and workspace isolation.

**Initial findings.** IndexedDB retained originals without a cache budget or expiration. Export could succeed while omitting Cloud originals. Cloud sync could overwrite restored content; transport state was also restored. Append aborted on conflicts despite promising skips, and imports rejected another workspace's identity. An 8 MiB file produced a 10.7 MiB JSONL line, followed by another validation read. The existing 27 backup tests did not qualify large Cloud recovery.

**Safety rule.** Evict only redundant bytes with a verified, currently available remote original in the same workspace/provider; a `storage_id` or historical “done” status is insufficient. Protect local-only, pending, running, retrying, failed, cancelled-but-uncommitted, and unclassified legacy originals. Recheck eligibility atomically across tabs before eviction; uncertainty means retain. Never delete remote objects, metadata, or references during cleanup. If protected files exhaust capacity, refuse new intake. Static originals never expire automatically.

**Starting defaults.** Cloud: **10 MiB per cached original**, **250 MiB total reusable cache per browser origin**, and **14 days since last successful use or upload**. Evict eligible least recently used copies sooner under pressure; protected staging is never reclaimed. Static: keep the **20 MiB default**, enforce a **50 MiB absolute per-file ceiling**, and check storage capacity before intake. Preserve existing oversized originals.

**Controls.** Deployment admins use **Admin → Workspaces → select workspace → Cloud files and browser cache**; owners use **Admin → File settings**. Save cache size, budget, retention, and upload limits without restarting.
