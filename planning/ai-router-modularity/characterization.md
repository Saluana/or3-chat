## Reproduced defects and fixture repairs

- **Confirmed, repaired separately: model-filter reasoning.** The native durable-boundary integration case selected a low-effort-only model through `ai.chat.model:filter:select`, but the captured request used the original model's `high` effort. The pre-fix run records the mismatch; reasoning is now resolved from the selected model's metadata, and the same case passes in the post-fix run.
- **Confirmed, repaired separately: Online provider projection.** Direct and independently authorized server requests previously admitted the model hint before adding the search tool, allowing a request whose actual provider body exceeded the captured context limit. The direct usage fingerprint also described different model/tool configuration from the upstream request. All three regressions failed before the fix and pass afterward. Client/server admission, preview, lossy inspection and background usage now count the provider projection while the legacy host envelope still goes through the existing server tool-validation boundary.
- **Confirmed fixture drift: background detach.** The original fake DB did not support the newer KV preference lookup or its hook engine; it failed before the lifecycle checks. The fixture now provides KV reads/writes and the same scripted hooks to both import paths, while its real IndexedDB case uses real transaction table selection. The complete owner suite passes **67/67** (`phase2/background-fixture-final.log`).
- **Confirmed browser fixture drift.** The production context-meter and Cloud bridge fixtures had not saved per-chat tool settings, and the deletion journey selected an old temporary title after the fixture generated a permanent title. After correcting the fixture setup, the three local browser cases and the three authenticated SQLite handoff/reconnect cases pass with their existing policy gates and assertions (`phase2/browser-fixtures.log`, `phase2/cloud-fixtures.log`). Original baseline artifacts remain under `baseline/cloud-run`.
- **Intentional existing policy:** missing `supported_parameters` currently permits the existing OpenRouter tool path; the per-chat tool gate and runtime authorization are separate. An explicit list without `tools` excludes tools. This must remain an OpenRouter-specific policy, not a universal adapter default.
- **Metadata normalization disposition:** client readiness and trusted server admission both remove a final legacy thinking hint and then the recognized routing hint; exact catalog IDs win over aliases and stale cache provenance remains explicit in `model-context-readiness.test.ts`. The delegated catalog has its own matching policy. The legacy `:thinking` collision is an intentional existing ambiguity, demonstrated by `phase2/thinking.log`; the router boundary must not treat it as a universal suffix rule. Whether every delegated alias behaves identically remains unresolved and is a phase-5 qualification concern.
- **Tracker ownership disposition:** `useAi.ts` currently owns view subscriptions and foreground reconciliation in addition to the existing background tracker. This is confirmed architectural coupling, not by itself a reproduced user-facing defect. Its extraction requires the existing 67 lifecycle cases and Cloud handoff receipts to remain green.
- **Added end-to-end search boundary:** the canonical local tool journey selects Web search in the UI, runs a local tool once, and records both provider requests; the authenticated SQLite worker fixture independently rejects a missing, duplicated or incorrectly routed search tool on either iteration. These exercise the real saved selection and job loop rather than a new test-only runtime switch.
- **Legacy collision characterization:** a browser fixture supplies both a base catalog ID and a genuine ID ending in `:thinking` with different supported efforts. The captured request establishes which model and effort the existing public string path selects; a future neutral adapter must not inherit this OpenRouter-specific interpretation.
- **Additional browser contracts:** the free-model fixture has distinct paid and `:free` IDs and captures Off and Nitro requests. The hook fixture records pure filters, durable row acceptance, before-send, completion and after-send around one real browser turn.

The pre-fix core run is `test-results/ai-router/phase2/pre-fix-core.log`; it includes the intentionally unresolved nonshipping adapter constructor. The candidate-focused run is `post-fix-core.log`: the four request/model suites pass; its remaining 50 errors were from the background fixture and are resolved by the separate 67-case run above. The adapter contract remains deliberately failing until the production constructor is introduced. These results do not turn the original failed Gate A into a passing baseline, and Gate B remains open until its other cases are qualified.

## Boundary qualification in progress

The first adapter integration keeps the host server envelope and trusted context admission intact, but moves the direct provider projection and both foreground decoders through one runtime. The same runtime executes the opaque-ID fixture. Catalog SDK construction now belongs to `shared/openrouter/catalog.ts`; the existing model service still owns the only browser cache. `phase3/core.log` records **507 passed, 1 skipped** across 14 focused suites. `phase3/browser.log` and `browser-results.json` record **5 passed** real browser journeys covering search/tool follow-up, Help Chat, legacy thinking ambiguity, free identities and hook order. This is not yet a passing phase-3 gate: nonstreaming/secondary consumers, server composition and tool events for the nonshipping adapter remain to be qualified.

The host job transport and a first view/history extraction are separately qualified. The first extraction run exposed a missing context-admission error import in the retry path; `phase3/extraction-core.log` preserves that failed result. After restoring it, `phase3/extraction-core-fixed.log` records **331 passed, 1 skipped**, including uncertain-admission and no-duplicate lifecycle cases. `phase3/extraction-cloud.log` records **2 passed** against the disposable authenticated SQLite profile, including Online tool execution and one-time client handoff. Further view subscriptions and native execution remain in the composable, so phase 4 is still open.

The nonshipping adapter also needs a browser qualification with the real normalized-stream reducer. Credible failures are that a shared runtime strips a colon-bearing ID, expects OpenRouter SSE, drops or reshapes a tool event, or dispatches an explicitly unsupported option. The test-only fixture sends a different JSON response through the production constructor and asserts the reducer's text and pending tool state as well as the dispatch count.

For the model-option presentation, another credible failure is treating a router without Web search as though it supports OpenRouter's option. The same browser fixture exposes an empty descriptor list and separately rejects explicit search and routing options before dispatch; the OpenRouter menu continues to use its existing labels and ordering.

The remaining governed-completion HTTP qualification must exercise a real installed, grant-reviewed package and the real governor together. Credible failures include disclosing the host key, accepting an unapproved model or plugin-chosen endpoint, bypassing the output or spend limit, treating missing usage as free, or honoring an activation after its plugin is disabled. The scripted provider records only request bodies and whether the expected synthetic authorization was present.

The existing automatic-memory integration already captures both bodies, but must also assert the extraction model, output bound, reasoning policy, schema and both fixed destinations. A regression in any of these could change cost or expose a key to a different host while still producing a valid saved memory.
