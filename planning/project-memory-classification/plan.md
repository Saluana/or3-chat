# Project memory without user-facing categories

**Goal.** Keep facts and decisions as internal metadata. Users see one Memory list and one Save memory action, with normal text editing and deletion. Remove category selectors, category badges, and the blanket “review existing decisions” checkbox. This change simplifies explicit memory saves; automatic collection from every chat remains outside its scope.

**Research.** OpenRouter Decisions evaluates supplied content and returns typed probabilities; it cannot write or summarize memories. Use a `choice` question with fact, adopted decision, and uncertain outcomes. Both [GPT-6 Luna Decisions](https://openrouter.ai/openai/gpt-6-luna-decisions) ($0.10/M input tokens) and [Jev 1.13](https://openrouter.ai/typesafe/jev-1.13) ($0.042/M) currently support this use case, with no output-token charge. These are candidates, not evidence of accuracy on OR3 memories. OpenRouter recommends calibrating questions and thresholds against representative examples. [Decision model guidance](https://openrouter.ai/skills/openrouter-decisions)

**Design.** Reuse `ProjectMemorySchema`, `saveProjectMemory`, the captured workspace scope, existing provenance checks, and the shared Project Context Builder. Keep the current IndexedDB representation and existing records; no migration or bulk reclassification is required. Route message saves, manual additions, accepted handoff suggestions, and edits through one application-level save helper.

1. Save the user’s exact text immediately using the existing neutral `fact` default, then close the form. Classification never delays saving, sending a chat, or clearing its input.
2. Make one bounded auxiliary request containing that text and, where available, up to six nearby source messages from the owning chat, capped at 16 KiB total. Ask whether the memory represents background information, an adopted choice, or insufficient evidence. Assistant suggestions, rejected options, hypotheticals, and quoted instructions do not establish adoption. Missing context produces uncertainty.
3. Validate the typed response and apply the calibrated decision threshold. Update only `kind` through the existing expected-clock writer. Capture the operation independently of sidebar visibility. Recheck workspace access, project ownership, source evidence and the saved text/clock before dispatch and commit; a later edit, deletion, move or revocation invalidates the result.
4. On uncertainty, offline state, missing credentials, malformed output, or a three-second deadline, retain ordinary saved reference context. No automatic retries or durable queue. Classification cannot rewrite text, create additional memories, replace another memory, or grant tool permissions. Existing conflicts stay visible in the saved content; removing the blanket checkbox does not authorize silent replacement.

Use the installed `@openrouter/sdk` Decisions method, existing key handling, and a narrow authenticated SSR proxy following current authorization, rate-limit and key-precedence patterns; static/BYOK installations retain a direct path. The installed SDK needs the root base `https://openrouter.ai` for `/api/alpha/decisions`; the chat base currently produces a doubled path. Disable its default long retry policy. One internal pinned model setting controls the classifier, with no project configuration panel or runtime model cascade. Start evaluation with Luna and compare Jev; ship the cheaper candidate that meets the acceptance bar. Record model, probabilities, latency and cost in diagnostics without logging memory text.

**Implementation receipt (2026-10-07).** The shared save pipeline, authenticated proxy and category-free forms are implemented. Real OpenRouter qualification found and fixed rejection of dated provider model IDs and clarified the rubric so an explicit report of approval is sufficient evidence. The selected Jev model at 0.9 also passed a separate 50-request run including ten held-out examples, with no unapproved choice promoted.
