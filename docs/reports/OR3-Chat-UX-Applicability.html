Which chat complaints still apply to OR3?

Retry keeps alternate answers, and synced devices agree on which answer to use for the next message. Split panes also keep their own model choices. Continue after a model’s output limit remains open.

The short answer

Complete

Retry preserves the selected answer

Two browser profiles chose different answers offline. After their changes merged, each showed the same answer and sent it once in a follow-up. All three versions were still available.

Complete

Each pane keeps its own model

After reloading two chats with different catalog choices, each sent its next request using the model selected in its own pane.

Measure

Time the wait to open a long thread

Only a few message rows reach the screen, but opening the chat still processes its full history. A desktop comparison below measures that interaction at three sizes.

Keep

Keep the current scroll behavior

All 13 Chromium scroll checks passed. The next meaningful checks are momentum scrolling on real phones and returning to a reading position after a hard reload.

01Retry keeps earlier answers and both devices agree on the selected versionUse Retry on the latest turn, browse answers with the arrows, or branch from an earlier turn. A saved edit is used on the next request.Complete

Retry and editing. Retrying creates another version. Editing a prompt or reply keeps its place in the conversation and marks the saved change Edited. Older turns retain Branch.

Cross-device selections. Two isolated Chromium profiles started with three versions of the same answer. One chose version 2 and the other chose version 3. After exchanging changes through OR3’s sync conflict resolver and reloading, both showed one prompt and the same answer. The arrows still reached all three versions. A follow-up sent from each profile contained the original prompt and selected answer exactly once. Continuing a later stopped reply also sent that same answer exactly once.

Reload during an edit. Chromium prompted before leaving a failed prompt’s in-progress save. After cancelling the reload and seeing Edited, reloading proceeded normally. Explicit Retry sent the corrected prompt once.

Peer example · NextChat #5514

03An answer cut off by the model can look finishedContinue works for an interrupted reply, but a provider’s output limit can leave the user with half an answer and no Continue button.Implement / fix

In OR3. The OpenRouter parser emits a truncated completion on a length limit. The direct OpenAI adapter also represents incomplete responses. The foreground handler and the continuation loop discard the terminal event’s detail. The message component only offers Continue on nonempty assistant replies marked with an error. A synthetic length-limited stream verified the parser signal.

Decision. Carry the output-limit reason through persistence and expose Continue on resumable, nonempty replies. Distinguish a token cap from a refusal or another non-resumable stop.

Acceptance check. Return a short answer ending at an output limit. After reload, the user should see the cutoff and be able to append a continuation to the same reply.

OpenRouter limit OpenAI incomplete Foreground loop Continue loop Button condition
04Long threads still cost more to openOR3 renders a window of messages and updates the streaming row in place. Before a pane shows a saved chat, it still reads and processes the entire thread.Verify

In OR3. The pane loads all nondeleted rows, filters superseded turns, sorts the remainder, and reconstructs the chat and tool history. Switching waits for that work. A throttled, thread-scoped observer repeats it after relevant writes. In October, a separate rich code/math streaming fixture recorded about 33.3 ms between frames at p95 under 4× CPU slowdown. That historical measurement concerns streaming, a different operation from opening a thread.

Decision. Measure real thread switches and typing with long reasoning, code, tools, and attachments. If the full history read dominates, display the newest messages first and load earlier ones as needed. Keep the complete conversation available for model requests and preserve branch and compaction anchors.

Acceptance check. Compare 20, 500 and 5,000 messages on the normal /chat route. Record time to the newest visible message, input delay while streaming, and the reader’s position. See the desktop opening measurements below.

Peer example · NextChat #2393

05Structured reasoning works. Tag-only output needs a provider checkOR3 already separates and collapses structured reasoning. A synthetic tag-only reply could show reasoning inside the answer or lose the block from view.Improve

In OR3. OpenRouter reasoning fields and direct OpenAI reasoning summaries feed a collapsed, keyboard-operable disclosure. In an isolated parser and renderer probe, a split <think> tag inside ordinary answer text became text events. Inline contents appeared as answer prose, while a standalone multiline block disappeared. Code samples retained literal tags. Even when the disclosure is closed, the component updates its full text node.

Decision. Capture the output format of a supported model that exhibits this behavior. For that format, separate tag-delimited reasoning as chunks arrive and preserve literal code examples. Measure a large closed trace before deferring the mounting of its text until expansion.

Acceptance check. Exercise split tags, a literal example in a code fence, structured reasoning arriving beside answer text, and a long trace reopened after reload. Compare typing and scrolling with the disclosure open and closed.

Peer example · Open WebUI #33444

07The composer hint needs a contrast and accessibility fixThe Blank light theme’s placeholder is faint, and the composer’s textbox omits the multiline accessibility attribute.Improve

In OR3. In the running Blank light composer, Chromium reported the placeholder as #666 at 78% opacity over a white shell. That composites to roughly #888, or 3.56:1 against white. The theme supplies its own placeholder override. WCAG’s normal-text AA threshold is 4.5:1. Main text uses a darker token and Markdown has a semibold weight. This is a finding about a specific control and theme.

Decision. Use a placeholder color that meets the threshold after compositing. Mark the composer as a multiline textbox. Check rendered text, focus rings, 400% zoom and screen-reader announcements in the bundled themes before drawing conclusions about the rest of the UI.

Acceptance check. The empty enabled composer should meet 4.5:1 in Blank light, stay legible in dark mode, and be announced as a multiline input.

Peer example · Open WebUI #27601

08Enter depends on window width and needs real IME coverageBelow 768 px Enter inserts a line. At wider widths it sends. A tablet and a narrow desktop can therefore behave differently from what their keyboards suggest.Verify

In OR3. ProseMirror already suppresses key events during tracked composition. OR3’s own send binding does not independently guard a late composition-ending Enter. OR3’s search palette already handles composition-end timing and replay. The review established a coverage gap for Japanese and Chinese input. An accidental send was not reproduced.

Decision. Verify Japanese and Chinese candidate confirmation on real keyboards, including Safari and Chrome. If an event reaches Send prematurely, use the palette’s tested timing approach. A focused send-key preference and a visible hint would address the width-based surprise without a full shortcut editor.

Acceptance check. Confirm a candidate with Enter, then press Enter deliberately to send. The first key should only commit the word. Repeat with Shift+Enter, on a wide tablet, and in a narrow desktop window.

Peer example · Open WebUI #17975

09Full-text search finds the chat, then leaves you to find the messageThe sidebar’s title filter hands off to workspace-wide search. Search can match saved message text, but its Open action targets only the thread.Improve

In OR3. The search index includes saved user and assistant message bodies. A historical 10,000-chat fixture with 104,990 messages returned history in batches of 500 rows. Full indexing still took around 3.1–3.4 seconds on the recorded desktop setup. Index build time and the time for a query against an existing index are different measures.

Decision. Carry the matching message ID into the Open action, restore that row in the virtual viewport, and highlight the excerpt. Keep search scoped to the current workspace and respect canonical visibility for retried turns and branches.

Acceptance check. Search a sentence buried hundreds of turns back. One activation should reveal its source message, including after closing and reopening the chat.

Peer example · NextChat #4543

10Streaming already yields when the reader scrolls awayOR3 follows at the bottom, holds a visible message steady while reading earlier turns, and provides an explicit way back to the latest reply.Already handled

In OR3. The scroll component tracks reading intent and anchors rows through late height changes. Editing suspends bottom-follow. Tabs capture an anchor for same-session switches. All 13 fresh Chromium canary tests passed, including a user scroll overtaking a pending follow, an offscreen tail growing, and switching threads. The fixture mounts the real scroller on 100 mixed-height rows.

Decision. Keep the existing behavior. A hard reload restores the tab but omits its reading anchor from durable layout storage. If reload continuity matters, persist a message ID and offset per tab. A permanent auto-follow toggle is lower priority than checking touch and momentum scrolling on devices.

Acceptance check. Browse above a reply during sustained generation, switch apps, and return. Resume following via Jump to latest. Test a reload separately because it has a different persistence contract.

In OR3. Streaming Markdown reuses completed blocks, and a syntax worker failure leaves code readable. The math journey verified that code stays literal and prose math renders after reload. The Mermaid renderer leaves source and a status message when diagram rendering fails. Long lines and wide tables still deserve a narrow-screen check.

Decision. Keep the renderer and its streaming regression coverage. Add one malformed Mermaid example and a long-line copy check on a phone if those paths regress. Consider an optional code-wrap control only if horizontal scrolling proves painful.

Acceptance check. Paste a Python comment, a formula and a code fence with dollar signs. An invalid Mermaid diagram should expose its source and an error. Copying a long code block should preserve its contents.

Peer example · LobeHub #3858

12Nested folders and sidebar controls already existProjects support folders within folders, chat creation inside a folder, and moving existing items. Global Chats remains chronological with pinning and Add to project.Already handled

In OR3. The sidebar has a named toggle, a mobile drawer and a saved desktop collapse state. A user looking only in global Chats could still miss the project organizer. Removing a chat from daily view without deleting it is a separate job. There is no dedicated nondestructive archive action in the global list.

Decision. Keep the project folder structure. If people struggle to organize a first chat, surface Add to project and explain where its folders live. Add Archive only if users need a reversible way to declutter global Chats.

Acceptance check. Ask a new user to move an existing chat into a nested folder and reopen it on a phone. Watch whether they can find the project entry point and return to the same conversation.

Evidence & limits

Retry and model selection verification

The initial review at 1ab53e8f verified split-pane model choices and identified the retry sync conflict. The local closeout reproduced that conflict before the fix and exercised it again with two Chromium profiles, real IndexedDB records, the production merge code, and captured requests to a fixture provider. The edit recovery check also exercised a browser reload while a save was in progress. All five targeted Chromium journeys passed on a fresh server. The focused suite passed 259 tests with one existing skip. The typecheck and documentation checks passed. A live Cloud server and a paid model provider were outside these checks.
